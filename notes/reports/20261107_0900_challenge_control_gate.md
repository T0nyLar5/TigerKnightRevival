The name strings are not in Kingdom-Win32 exe, SyncClient.dll or Sync.dll, so they must be filled by native code through the property (offset), probably from the weapon / a server-side or sync data path that never ran. If any of them is 0, MaxSpeed = GroundSpeed*factor = 0, which fits every verified symptom: Acceleration 3000 but Velocity 0, forced Velocity=300 clamped back (opt 6 mode 4 moved 0.07), air movement fine (falling ignores it), no ReqMove on W (sender is velocity-driven: report 20261106_1900), no walk anim (BlendBySpeed 0), sprint impossible. 2. **H1 challenge not started: low.** KingdomChallengeGame/KingdomChallengePlayerController script (tools\work\d4\ChallengeGame.uc, d4\KingdomChallengePlayerController.BattleStart/BattleWait, decomp\...PlayerTick/ResetPlayerMovementInput) only blocks move input via `bIgnoreMoveInput=1` when `Game.IsChallengeEnd && PlayMode>0` (PlayerTick) and `IgnoreSomeInput(true)` at stage-4 end. Note: the map 3/11 tests used the same gameMode from joinMatch with TK_MAPID override (server\handlers.py:611), so they were likely also KingdomChallengeGame -> "fails on 3/11" does not rule H1 out by itself.
