# ue_inspect: find the hero Pawn via UE3 object table (11-06 23:00; built, NOT run in game)

## Tool
- `tools\ue_inspect.py`; launcher `英雄速度檢查.bat` (1 read, 2 read + fix with y/n, 3 = old position scan pawn_probe). Output also in `server\logs\pawn_probe_last.txt`. `--static` prints static candidates; `--selftest` runs on a synthetic heap.
- Exe facts (verified from file): Kingdom-Win64-Shipping.exe is unpacked, ImageBase 0x140000000, .data RVA 0x1770000 size 0x23cd90.
- Static candidates (verified, deterministic; code pattern `mov r,[rip+X]` then `mov r,[r+idx*8]`): 0x1922bd0 (169 refs, almost surely GNames), then 0x18a0870 (18), 0x1936c68 (8), 0x1922bf0 (4; 0x9c329 loops it as a ptr array, count at +8), 0x1934210, 0x19386d8 (4 each). GObjObjects NOT pinned statically (hypothesis: one of these or an array accessed via other code), so the runtime does the real work.
- Runtime algorithm: (1) scan the module .data for TArray-like slots (ptr, count<=max, 500..16M), static candidates first. (2) GNames = slot whose entry 0 string is "None" and entry 1 "ByteProperty" (learns string offset, ANSI/UTF-16). (3) GObjObjects = other big slot where the object "Class" has Class pointer == itself and name "Class" (learns Name and Class offsets; self-check, no assumed layout). (4) Outer offset = field of property GroundSpeed pointing at class "Pawn". (5) UProperty.Offset field = the dword (0x58..0x130) where the six Pawn floats GroundSpeed..JumpZ have distinct multiple-of-4 values, increasing, with ElementSize==4 just before. (6) live Pawn = class name contains "Pawn", object name not Default__; hero = PlayerController.Pawn (property Controller.Pawn). Prints GroundSpeed/AirSpeed/AccelRate/JumpZ/Physics(enum number+name)/Velocity/Acceleration, controller IgnoreMoveInput raw dword, plus the first non-hero Pawn of each other class (AI soldier values for comparison).
- Fix (menu 2): shows plan, asks y; only GroundSpeed/AirSpeed (<10 -> AI soldier value else 450) and AccelRate (<100 -> 2048); nothing else.
- Tested: selftest on a synthetic heap (layout name 0x48/class 0x50/outer 0x40/propOffset 0x90) passes: discovery recovers all offsets and the hero. Static search verified on the real exe. Not run against the real game.

## Risks (hypothesis)
- Real UE3 Win64 layout of FNameEntry/UProperty may differ in ways the heuristics do not cover (e.g. TArray in a non-.data section, GObjObjects as a different container, property name "Pawn" outer not "Controller"). Then the tool prints which step failed (GNames / GObjObjects / Outer / Offset) -> report that line.
- Class "Class" must be among the first 60000 objects (true in stock UE3).
- Hero found only if PlayerController.Pawn is set; otherwise [其他] lines show the pawns that exist.
- Scan time 10-40 s (many ReadProcessMemory calls).
- Run as administrator if OpenProcess is denied.
