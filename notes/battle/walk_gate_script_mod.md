## Script mod pipeline (KingdomGame.u patching, 11-05)
Files: `tools\upkg.py` (export table reader), `tools\upatch.py` (patch list + build), `tools\upenc.py` (re-encoder + own LZO1X compressor).
- Build: `tools\.venv\Scripts\python.exe -I tools\upatch.py build [--with walk_look_gate] [--only name,..]` -> `server\mods\KingdomGame.u` (gitignored, 156 MB). Needs `tools\work\KingdomGame_plain.u` (from `updec.py plain`). It refuses an original that is not the unmodified Steam file (sha256 in upatch.py).
- Add a mod: append a dict to `PATCHES` in upatch.py: `export` (e.g. `KingdomPlayerInput.PlayerInput`), `edits=[(old_hex,new_hex)]` of EQUAL length; `old` must occur exactly once in that export's data. Same length means no offsets move.
- upenc splices: header + every chunk whose plain bytes equal the base plain keep the original encrypted bytes; only changed chunks are re-compressed (128 KB blocks, xor from 0x2a) and the plaintext chunk table (0x75) is rewritten. Encoding the unpatched plain reproduces the original file byte for byte (sha256 equal). `upatch.py verify-full OUT` decodes everything with updec and compares (done: equal).
- User side: `套用走路修改.bat` (backs up the original once to `server\mods\backup\`, only if size == 156001509; copies mod; fc /b verify; refuses while the game runs) and `還原遊戲規則書.bat`. Game file: `<game>\KingdomGame\CookedPC\KingdomGame.u`.
- Patch `walk_move_gate`: PlayerInput() script offset 0x62d (export data +1629, plain file 0x6cd974) = `JumpIfNot 0xA1B <OrOr(GRI==none, !bMatchHasBegun, IsMoveInputIgnored())>` (117 bytes); condition replaced by `EX_False` (0x28) + 113 x `EX_Nothing` (0x0b), so the "zero aForward/aStrafe/aUp" body is always skipped. Dc.exe now shows `if(false)` (the Nothing padding confuses its nesting display afterwards, harmless to the VM).
- Optional `walk_look_gate` (off by default): same for aTurn/aLookUp (data +1779, 117 bytes). No other script gate on movement exists: sc.exe grep of bMatchHasBegun/IsMoveInputIgnored/bIgnoreMoveInput shows only PlayerInput, CatchDoubleClickInput (double-click dodge, uses IsMoveInputIgnored), Spectating/stun code, ProcessMove has none. If walking still fails, native IsMoveInputIgnored/bIgnoreMoveInput in PlayerWalking or server-side ReqMove handling is the next suspect.
- Checksum risk: no check found. Chunk table is plain, no whole-file hash/size field in the header; exe strings show no md5/crc/verify of .u. Client sends two 32-hex file hashes in MsgMD5Check (0x3ec) to the server; our fake server ignores them. Steam "verify files" will revert the file.
